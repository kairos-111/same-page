# Same Page 安装包规划（Mac + Windows）

> 2026-10-25 · 规划稿。**2026-10-26 进度：** Mac 部分（M1–M7）未开始；Windows 部分的 W1–W5 已在 Windows 版构建中基本完成，安装包已出但未在真机运行，W0 真机实测仍是第一步（见 PRD 第 5.4 节）。目标：朋友下载安装包后直接装、直接用，不需要装开发工具，也不需要懂命令行。
> 本文只是规划；实施前由用户确认第 9 节的决定，之后按阶段逐个做，每个阶段单独测试和提交。

---

## 1. 目标与边界

**要达到的效果**

- Mac：朋友下载一个 DMG，拖进"应用程序"，打开后按引导授权麦克风，就能开始翻译。
- Windows：朋友下载一个安装程序，双击装好，打开后按引导操作，就能开始翻译。
- 两个平台功能一致：三种识别语言（英语、俄语、混合试用）→ 中文；有记录库、回放、导出和运行数据。
- 装好后识别和翻译全部在本机完成，不上传，也不需要账号。

**这次不做**

- 不上架 App Store 或 Microsoft Store，不面向公众发布，不收费。
- 不加云端 API，不加账号，不改产品功能。交互改版另按 PRD 第 13 节进行。
- 不支持 Intel Mac（原因见 2.2）。

## 2. 现状核对（2026-10-25 实查）

### 2.1 现在的应用包

| 部分 | 大小 | 说明 |
|---|---|---|
| 模型 | 3.0 GB | Turbo 1.5 GB、Hy-MT 翻译 1.1 GB、Small 459 MB |
| Python 运行环境 | 1.3 GB | 其中 PyTorch 542 MB，**只用来给静音检测传数据**；另有 llvmlite 125 MB、scipy、sklearn、sympy 等不一定用得到的依赖，以及 Mac 上用不到的 faster-whisper/ctranslate2 |
| llama.cpp | 31 MB | 只需要 `llama-server`，其余 20 多个工具都可以去掉 |
| 合计 | **4.4 GB** | |

### 2.2 只能在这台电脑上用的地方（必须先修）

| 问题 | 影响 | 位置 |
|---|---|---|
| **收音组件的最低系统版本是 macOS 26** | 编译时没有指定目标版本，朋友如果是 macOS 14/15，收音组件直接打不开，麦克风和电脑声音都用不了 | `scripts/build_native.py`（swiftc 没有加 `-target`） |
| 识别引擎 MLX 要求 macOS 14+ 和 Apple 芯片 | 最低只能支持 **macOS 14 + M1 及以后的芯片** | `mlx` 依赖 |
| 只有临时签名 | 朋友打开时会提示"无法验证开发者"或"已损坏"；每次更新后签名都变，麦克风和屏幕录制权限可能要重新授权 | `bundle_local.py` / `work/deploy.sh` |
| 模型放在 .app 里面 | 每次更新都得重新下载 4 GB；用付费签名公证时，体积大，上传也慢 | `paths.py` 中的 `MODELS = ROOT/...` |
| 打包内置的 FFmpeg 是 GPL 版本（含 x264） | 给别人分发时需要附上源码获取方式；我们只用它解码导入的文件，换成 LGPL 的解码库即可 | `imageio-ffmpeg` |
| 三个模型启动时全部加载 | 8 GB 内存的 Mac 可能卡顿，或被系统强制结束 | `desktop.js` 中的 `autoStartModels` |
| 数据目录叫"听课"，Bundle ID 是 `app.tingke.local` | 能用，但对朋友来说名字奇怪；改 ID 又会让你这台电脑上的权限失效 | `main.rs` 中的 `layout()` |
| 没有"干净电脑"测试 | 不确定在别的电脑上是否还依赖本机文件 | — |

**已核对没问题的：** 桌面程序和 Python 的最低系统版本都是 macOS 11；llama.cpp 用 `@rpath` 链接，可以整体搬到别的位置；Hy-MT2-1.8B-GGUF 采用 **Apache 2.0** 许可，可以分发（需附带 LICENSE）；Whisper 采用 MIT 许可。

### 2.3 Windows 那边能复用的

- **能复用：** 桌面外壳 Tauri、FastAPI 后台、网页界面、记录存储、翻译调度、llama.cpp。
- **已经装了：** 识别框架 whisperlivekit 自带 `FasterWhisperASR` 后端，和现在用的 MLX 后端是同一套流式确认逻辑，而且 faster-whisper 已经在依赖里。所以 Windows 版不用重写识别流程，只要换掉模型推理这一层。
- **必须新写：** 收音组件。Mac 用的 Swift + ScreenCaptureKit 在 Windows 上没有对应物。
- **需要适配的代码：**
  - `asr.py` 和 `asr_quality.py` 按 MLX 的返回格式（字典、`sample_len`）写。faster-whisper 返回对象，参数名是 `max_new_tokens`。
  - `language_detection.py` 用 MLX 做语言判断，要换成 faster-whisper 的 `detect_language`。
  - `runtime.py` 用 MLX 预加载权重并释放显存。
  - `main.rs` 写死了 `Resources/engine`、`~/Library/...`、`bin/python3.12`，结束进程用的是 `/bin/kill`。

## 3. 总体方案

### 3.1 应用与模型分开

```
安装包（小）                     模型包（大，只装一次）
├─ Same Page 程序                ├─ Small 识别
├─ Python 运行环境（精简后）      ├─ Turbo 识别（可选）
├─ 收音组件                      └─ Hy-MT 翻译
└─ llama-server
        │                                │
        └──────────→  用户数据目录  ←─────┘
                      ├─ models/      模型
                      ├─ sessions/    记录与录音
                      └─ logs/        日志
```

- **模型存放位置：** 不再放在 .app 里，统一放到用户数据目录：Mac 是 `~/Library/Application Support/Same Page/models/`，Windows 是 `%LOCALAPPDATA%\Same Page\models\`。
- **安装模型的两种方式：**
  1. **首次打开时下载：** 从你指定的地址下载，按 SHA-256 校验，断点续传，下载失败不会留下坏文件。
  2. **导入本地模型包：** 朋友从网盘下载 `SamePage-模型包-mac.zip`，在引导页点"导入"。适合网络差，或者希望完全离线安装的情况。
- **更新时只换程序：** 以后更新只下载几百 MB 的程序，记录和模型都不动。
- **你这台电脑：** 继续用原来的"听课"目录，第一次打开新版时自动识别旧位置，不搬数据，不丢记录。

### 3.2 两个平台的组件对照

| 组件 | Mac | Windows |
|---|---|---|
| 桌面外壳 | Tauri（现有） | Tauri（同一份代码，按平台分支） |
| 后台 | 内置 Python 3.12 + FastAPI | 内置 Python 3.12 + FastAPI（Windows 版 python-build-standalone） |
| 识别 | MLX Whisper（Apple 芯片 GPU） | faster-whisper / CTranslate2：有 NVIDIA 显卡用 CUDA，没有就用 CPU int8 |
| 静音检测 | Silero VAD（onnxruntime，去掉 PyTorch） | 同左 |
| 翻译 | llama.cpp Metal 版 | llama.cpp **Vulkan 版**（NVIDIA、AMD、Intel 显卡都能用），不行就退回 CPU 版 |
| 收音 | Swift + ScreenCaptureKit（现有，需修正系统版本） | **新写** Rust 小程序：用 WASAPI 录麦克风和电脑声音，输出和 Swift 版相同的 16 kHz PCM 协议 |
| 导入文件解码 | PyAV（LGPL，已在依赖中），替换 GPL 版 FFmpeg | 同左 |
| 安装包 | DMG（拖到"应用程序"） | NSIS 安装程序，装到当前用户目录，不需要管理员权限 |
| 签名 | Developer ID + 公证（可选，见第 9 节） | 微软 Trusted Signing（可选） |

### 3.3 按硬件分档（启动时自动检测）

| 档位 | 条件 | 默认加载 | 预期出字延迟 |
|---|---|---|---|
| Mac 标准 | M 芯片，16 GB 及以上 | Small + Turbo + Hy-MT | 和现在一样 |
| Mac 轻量 | M 芯片，8 GB | Small + Hy-MT；Turbo 需手动启动，并提示可能变慢 | 略慢 |
| Windows 显卡 | NVIDIA 显卡，6 GB 显存及以上 | Small（可选 Turbo）+ Hy-MT | 接近 Mac，**需实测** |
| Windows 普通 | 没有 NVIDIA 显卡，8 核以上 CPU，16 GB 内存 | Small（CPU int8）+ Hy-MT（Vulkan 或 CPU） | 明显慢，**需实测**，可能要把识别步长放宽到 1.5–2 秒 |
| 不支持 | Intel Mac；Windows 4 核或以下，或内存 8 GB 以下 | 不能开始翻译，给出明确提示 | — |

以上档位是初稿，Windows 的数字必须按 W0 的实测结果改。

## 4. 第一阶段：Mac 安装包

每一步完成后跑相关测试并提交。每一步都可以单独交付，不需要等全部做完。

### M1 让应用在别的 Mac 上也能跑

- 收音组件编译时加 `-target arm64-apple-macos14.0`，打包后检查每个可执行文件的最低系统版本都不超过 14.0，不满足就让打包失败。
- 桌面程序 `MACOSX_DEPLOYMENT_TARGET=14.0`，`Info.plist` 写明 `LSMinimumSystemVersion=14.0`。
- 不是 Apple 芯片或系统低于 14 时，启动直接提示"需要 Apple 芯片和 macOS 14 或更新版本"，不再进入后才报错。
- 全仓检查是否还有写死的本机路径、用户名或开发目录。
- **验收：** 在这台 Mac 上新建一个空白用户账号，从 DMG 安装，能打开、能授权、能录 1 分钟英语并保存回放。

### M2 精简运行环境

- 静音检测改为直接调用 onnxruntime（`classroom/vad.py`，约 30 行），去掉 PyTorch 及其依赖（sympy、networkx 等）。
- 导入文件改用 PyAV 解码，去掉 imageio-ffmpeg（GPL）。
- 打包时排除 Mac 上用不到的 faster-whisper/ctranslate2，以及 pytest、llvmlite/numba 等确认无用的库。每去掉一个，都跑识别、导入和混合模式测试。
- llama.cpp 只保留 `llama-server` 和它依赖的动态库。
- 用打包清单固定每个文件的来源和校验值。
- **目标：** 程序部分从 1.3 GB 降到约 0.5 GB，DMG 压缩后约 0.3–0.4 GB。
- **验收：** 关键测试全部通过；同一段录音在精简前后识别结果一致。

### M3 模型移出应用、首次安装模型

- `paths.py` 把模型目录改到数据目录；旧位置（应用内、开发目录）作为兼容读取。
- 新增模型管理接口：列出模型、下载（断点续传、SHA-256 校验、先下到临时文件再改名）、导入模型包、删除；以 `model-manifest.json` 为准。
- 设置页"本地模型"显示每个模型"已安装 / 未安装 / 下载中 N%"；Turbo 可以单独安装或删除。
- 磁盘空间不足时拒绝下载并说明原因。
- 制作模型包：`SamePage-模型包-mac-v1.zip`，包含 manifest 和三个模型。
- **验收：** 断网时导入模型包能用；下载中途断网再联网能续传；校验失败不会被当成已安装。

### M4 首次打开引导

- 第 1 页：欢迎页，说明本机处理、不上传。
- 第 2 页：安装模型（下载或导入），显示进度和需要的空间。
- 第 3 页：麦克风授权，附测试电平条（与 PRD U02 共用）。
- 第 4 页：可选的"电脑声音"授权，说明为什么系统叫它"屏幕录制"、去哪里打开，打开后需要重启应用。
- 按内存档位决定自动加载哪些模型（修改 `autoStartModels`）。
- 引导完成后不再出现，设置页可以重新打开。
- **验收：** 新用户账号从第一页走到开始翻译，全程不看文档也能完成。

### M5 诊断与反馈

- 设置页加"导出诊断信息"：打包成 zip，包括版本、系统、芯片、内存、模型状态、近期日志和最近 3 条记录的运行数据。**不含录音、字幕原文和译文**，导出前列出包含哪些内容。
- 崩溃或引擎启动失败时，错误页也有同样的按钮。
- **验收：** 导出的 zip 中没有任何识别文本或音频。

### M6 签名、打包与发布

- 打包脚本 `scripts/build_release.py`：一条命令完成编译、精简、签名、生成 DMG、计算校验值、生成发布说明；不覆盖已有产物，输出前检查磁盘空间。
- **不付费签名：** 临时签名，再附一页图文安装说明，教朋友去"系统设置 → 隐私与安全性"点"仍要打开"。
- **付费签名（Developer ID）：**
  - 开启 Hardened Runtime，所有 dylib/so 逐个签名。
  - 申请必要的 entitlement：`disable-library-validation`，以及麦克风/音频输入。
  - 用 `notarytool` 公证并 staple。
  - 收音组件必须用同一身份签名，确认权限弹窗里显示"Same Page"。
- DMG 带"拖到应用程序"背景和卸载说明（删除应用，加上可选删除的数据目录）。
- **验收：** 在另一台 Mac 上（朋友的，或借来的），从下载到开始翻译全程走通。

### M7 更新（可放到第一批朋友试用之后）

- Tauri updater：更新清单和程序包放在你选定的位置，用 Tauri 自己的密钥签名（免费，与苹果签名无关）。
- 正在翻译时不提示更新；更新只替换程序，模型和记录不动。
- 没有付费签名时，自动更新后系统权限可能要重新授权，需要在更新说明里写清楚。

## 5. 第二阶段：Windows 安装包

Windows 和 Mac 第一阶段可以同时推进；但 W0 的实测结果决定 Windows 是否值得继续，所以 W0 要最先做。

### W0 可行性实测（必须先做，需要一台 Windows 电脑）

- 写一个独立测试脚本：在 Windows 上用 faster-whisper（CPU int8 / CUDA）跑 Small 和 Turbo；用 llama.cpp（Vulkan / CPU）跑 Hy-MT；拿同一段 3 分钟英语录音，测每次解码耗时、出字延迟和内存。
- 最好测两台：一台有 NVIDIA 显卡，一台只有集成显卡。
- **判断标准：**
  - 普通档能做到出字中位数 ≤ 5 秒，Windows 版就继续做。
  - 做不到，就只支持"Windows 显卡档"，或者 Windows 版只做导入文件（不要求实时）。

### W1 平台抽象（Mac 上就能做，不影响现有功能）

- `classroom/platform.py`：集中管理数据目录、收音组件路径、llama-server 文件名、Python 路径和结束进程的方式。
- `classroom/backends/`：把识别推理抽象成统一接口，包括加载、带词时间戳的转写、语言判断、输出长度上限和释放；保留 `mlx_backend`，新增 `ct2_backend`。`asr.py`、`asr_quality.py`、`language_detection.py`、`runtime.py` 改为只依赖这个接口。
- 测试改为对两种后端都跑（假模型）。
- **验收：** Mac 上全部现有测试通过，行为不变。

### W2 Windows 识别

- 接入 `FasterWhisperASR`，统一返回格式：对象转字典，`no_speech_prob`，词时间戳。
- 输出长度上限对应 `max_new_tokens`；乱码过滤、恢复和质量门全部沿用。
- 模型用 CTranslate2 格式（Small、large-v3-turbo），放进 Windows 版模型包。
- CUDA 运行库体积大（约 1 GB+），作为"显卡加速包"单独下载，不放进默认安装包。
- **验收：** 英语、俄语、混合三种模式的合成样本在 Windows 上全部通过，结果与 Mac 版做对照。

### W3 Windows 收音

- 用 Rust 写 `samepage-audio.exe`（cpal / WASAPI）：
  - 麦克风采集。
  - 电脑声音回环采集（WASAPI loopback）。
  - 重采样为 16 kHz 单声道，stdout 输出 PCM，协议与 Swift 版一致（先输出 ready JSON，再输出数据）。
- 处理设备拔出、默认设备切换和 Windows 麦克风隐私开关被关闭这几种情况，并给出明确提示。
- **验收：** 耳机和外接麦克风都能录；播放视频时选"电脑声音"能出字幕；拔掉耳机不会导致整个应用崩溃。

### W4 Windows 桌面外壳与进程管理

- `main.rs` 按平台分支：
  - 资源目录、数据目录（`%LOCALAPPDATA%\Same Page`）、`python.exe`。
  - 结束进程用 Job Object：应用被强制关闭时，Python 和 llama-server 一起结束，**不留残留进程**（Mac 上出过这个问题）。
- WebView2：Windows 11 自带；Windows 10 由安装程序带上安装引导。
- 处理中文用户名路径和长路径。
- 后台只监听 127.0.0.1，不触发防火墙弹窗。
- **验收：** 任务管理器里强制结束 Same Page 后，没有残留的 python 或 llama-server 进程。

### W5 Windows 安装程序与签名

- Tauri NSIS 安装程序，装到当前用户目录（不需要管理员），带开始菜单项、桌面快捷方式（可选）和卸载程序。卸载时询问是否保留记录。
- **签名：**
  - 不签名：朋友会看到 SmartScreen 蓝色窗口，需要点"更多信息 → 仍要运行"；也可能被杀毒软件误报。
  - 签名：用微软 Trusted Signing（约 10 美元/月）。
- 用 GitHub Actions 的 Windows 构建机自动打包，并跑 Windows 单元测试；这台 Mac 负责 Mac 版。
- **验收：** 在一台从没装过开发工具的 Windows 电脑上，从下载到开始翻译全程走通。

### W6 Windows 引导与诊断

- 复用 M4 和 M5，加上 Windows 特有的说明：麦克风隐私开关、选哪个输出设备做电脑声音，以及显卡加速包。

| 轮次 | 内容 | 谁来测 |

  - 0.12.0：Windows 首个试用版。

  - GitHub 私有仓库的 Release：单个文件上限 2 GB，模型可以分开上传；朋友需要有仓库访问权限。
  - 网盘：国内下载快。
  - 自己的对象存储：比如阿里云 OSS 或 Cloudflare R2，方便应用内下载和自动更新。
- **许可文件：** 安装包里带 `第三方许可.txt`，列出 Whisper（MIT）、Hy-MT2（Apache 2.0）、llama.cpp（MIT）、onnxruntime（MIT）、PyAV（BSD，自带 LGPL 版 FFmpeg）、Tauri（MIT/Apache）等。

## 8. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| Windows 没有独立显卡时太慢 | 体验差，不像"实时" | W0 先实测再决定；配置不够时明确提示；可以只支持导入文件 |
| 不付费签名 | 安装步骤多，更新后权限要重新授权 | 写图文说明；人多了再买证书 |
| 杀毒软件误报（Windows） | 安装被拦截 | 签名，并向杀毒厂商提交误报 |
| 模型下载在国内慢 | 第一次安装卡住 | 提供网盘模型包导入；下载支持续传 |
| 混合模式在 faster-whisper 上效果不同 | Windows 混合模式变差 | W2 做对照；必要时 Windows 版混合模式先关闭 |
| 8 GB Mac 内存不够 | 卡顿或被系统强制结束 | 按内存档位加载模型，并在运行数据页显示内存 |
| 朋友的问题难复现 | 修起来慢 | 导出诊断信息，加上运行数据页 |

## 10. 建议顺序

```
第 1 周期   M1 → M2           （先让别的 Mac 能跑起来）
            W0（同时进行，需要 Windows 电脑）
第 2 周期   M3 → M4 → M5      （模型分离、引导、诊断）
            W1（Mac 上做平台抽象，不影响现有功能）
第 3 周期   M6 → Mac 朋友试用
            W2 → W3 → W4
第 4 周期   M7（更新）
            W5 → W6 → Windows 朋友试用
```

- **两条线互不阻塞：** Mac 线不依赖 Windows；Windows 线 W1 之后的步骤依赖 W0 的结论。
- **"周期"不代表固定天数：** 每个周期结束时有可交付的安装包或可验证的结果。
