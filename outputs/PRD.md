## 1. 用户痛点与产品目标

用户在俄罗斯上课，常接触英语、俄语、中文。现有在线翻译有误译、网络慢和卡住的问题；课堂讲话持续进行，用户不能反复点击提交或等待网络恢复。

第一阶段只做好英语→中文：选好音源后点击开始，持续看到英文和中文；中文及时出现，专业词、数字、单位、否定和条件关系尽量准确；网络中断不影响核心识别、翻译与保存。错误必须能追溯到英文识别、中文翻译及原始声音，便于下一次迭代。

产品判断：先使用本机可持续运行的轻量模型，通过收音质量、术语、分句和调度改善体验。不能仅靠加大模型、接入 API 或宣传“支持多语言”来推断课堂效果。速度与准确度发生冲突时，应保留可修订预览和清晰状态，禁止通过漏掉音频或擅自补写内容制造流畅感。

### 范围边界

- 当前实现：英语识别、简体中文翻译、单音源、单活动会话、本地保存。
- 后续预留：固定俄语→中文，再评估同一人中英俄切换；需实际混说样本验收。
- 单独研究：多人重叠说话与说话人区分。语言切换不等于多人识别，二者不得混用验收结论。
- 云端 API 可作为未来自愿启用的补充；当前未接入，离线链路必须始终独立可用。
- 本版不包含多人同时独立听译、系统开机自启、通用安装包、Windows/Linux 适配。

## 2. 真实环境与模型决策

已核对实际本机：MacBook Air（Mac16,13），Apple M4，10 核 CPU、10 核 GPU，16 GiB 统一内存，macOS 26.3.1 arm64。系统信息、内置显示器和 APFS 磁盘用于确认是用户 Mac，而非云端容器。最初可用磁盘约 265 GiB，仅代表当时快照。

| 组件 | 当前选择与依据 |
|---|---|
| 默认识别 | `mlx-community/whisper-small-mlx`，多语言权重，运行时固定英语；短样例上更及时 |
| 可选识别 | `mlx-community/whisper-large-v3-turbo`，停止会话后切换作课堂对照 |
| 流式处理 | WhisperLiveKit 0.2.26 的 MLX/OnlineASRProcessor 组件；未直接部署其完整网页应用 |
| 翻译 | Hy-MT2-1.8B GGUF Q4_K_M，本地 llama.cpp b11669；日志确认 33/33 层使用 Apple GPU |
| 推理环境 | 独立 Python 3.12.15、MLX 0.32.4、mlx-whisper 0.4.3；完整 Python 依赖见 `requirements.lock` |
| 采集 | Swift 原生程序：麦克风 AVAudioEngine；电脑声音 ScreenCaptureKit；文件用随依赖提供的 FFmpeg |
| 页面与服务 | 本地静态 HTML/CSS/JS、FastAPI、WebSocket；无需 CDN |

没有替换系统原有 Python。模型精确来源、revision、SHA256 和运行包校验信息在本机 `work/downloads/verified-manifest.json`；该文件与模型当前未纳入 Git。迁移问题见第 10 节。

### 存储和内存预算

模型文件约：Small 481 MB、Turbo 1,614 MB、Hy-MT 1,133 MB，共约 3.23 GB；只计算默认 Small + Hy-MT 则约 1.61 GB。以上是十进制文件体积，不是内存需求。

本机完整开发目录此前约 6 GiB，包含两个识别模型、翻译模型、下载包、环境与缓存。当前 `.venv` 约 1.3 GiB。短测进程及子进程 RSS 合计峰值约 2.6 GiB，未完整衡量 GPU/统一内存，不能当作总内存上限。

音频格式为 16 kHz、单声道、16 位 PCM。每小时原始 PCM 约 115.2 MB；正常保存还生成 WAV，并保留 PCM，因此两份约 230.4 MB/小时，另加事件和导出文件。导入原文件还会占用 `work/uploads/` 空间。当前无自动清理策略。

## 3. 用户流程与交互要求

### 3.1 开始一堂课

1. 双击 `outputs/启动课堂翻译.command`，或运行 `.venv/bin/python scripts/launch.py`。
2. 启动器创建脱离启动终端的后台服务；重复打开复用已有服务。打开网页不会自动录音。
3. 页面地址为 `http://127.0.0.1:8767/`。旧的 8766 是临时下载面板，不是产品入口；8768 是内部翻译服务。
4. 开始页只问“声音从哪里来”：三张卡片“教室里”（麦克风）、“网课 / 视频”（电脑声音）、“已有录音”（导入文件，可点选或把文件拖到页面任意位置）。课程名选填，点“开始听课”，等待模型加载后持续听译。
5. 模型放在折叠的“识别设置”里，“快速 · Small”为默认，“更准 · Turbo”可选；折叠标题旁始终显示当前选择。
6. 按 macOS 提示授予采集权限；权限或音源错误需在页面可见，不得只写日志。连接失败、模型未部署时开始按钮不可用，并在按钮下方说明原因与恢复动作。

页面在浏览器 `localStorage` 记住上次的音源、模型、中文字号、英文字号和“只看中文”设置（键名前缀 `tk.`）；因此选过 Turbo 后，下次默认仍是 Turbo，直到用户改回。

麦克风使用系统当前默认输入设备，尚无设备选择器。电脑声音捕获其他应用播放的音频，尚无按应用选择。一次只能使用一种音源，尚不能混合麦克风和系统声音。导入文件上限为 1 GiB，实际可解码格式取决于 FFmpeg；不是所有后缀都已逐一验证。

### 3.2 听译与停止

开始后切换到全屏字幕页，其他控件让位于字幕：

- 顶部细栏：录音状态点、已收音时长、课程名、五格音量；右侧“只看中文”、中文字号“中 − n +”、英文字号“英 − n +”（各 8 档 13–36px，默认均 17px，中英同大；键盘 `+`/`-` 调中文；只看中文时英文字号不可调）、“详情”、“结束”。
- 段落：连续的多句合成一段，每段左侧时间戳，宽屏左英右中两栏并排，≤900px 改为英上中下。换段规则：与上句间隔超过 4 秒；或上句已以句末标点定稿且本段已满 6 句 / 420 个英文字符 / 50 秒；超过 672 字符强制换段。鼠标指向一句时，中英对应句同时高亮。
- 逐字出现：英文与中文新增文字按约 40ms 一跳逐步出现，剩余越多每跳越多，避免积压。
- 平滑修正：新文本与已显示文本开头不一致时，只淡出差异部分（0.5 秒），再淡入新内容（1.4 秒）；过渡期间该句锁定，期间到达的更新排队，结束后再应用最新版本。
- 原文更新时保留上一版中文，逐句标记“旧译文 · 中文待更新”；无中文时标记“等待中文”并保留末尾光标。悬停状态可查看中英版本号；版本匹配后移除标记，旧译文不得冒充当前版本。
- 翻译失败或响应不完整时标记“翻译未完成”，即使保留了旧中文也提供“↻ 重新翻译”（会话运行中）。
- 恢复快照、切换标签页回来或查看已结束的课时，直接显示完整文字，不播放动画；系统开启“减少动态效果”时同样不播放。读屏器只在每句中文完成时朗读一次。
- 默认自动跟随最新字幕（包括逐字增长时）；用户上翻即暂停跟随，底部出现“↓ 回到最新”。较早段落不再变淡。
- “详情”分别显示识别落后、待译队列（另列在途）、排队最久（不含执行）、当前执行已用、中文版本未跟上句数/最久时长、未定稿最久、内存估算及原有信息。中文未跟上时长参与 15/30 秒提示。
- 提示条只在异常时出现：连接中断、会话错误、收尾中、超过 5 秒无输入、识别落后或待译等待超过 15 秒（“字幕稍慢”）/30 秒（“落后较多”）。

“结束”需两次点击：第一次变为红色“确定结束？”，3 秒内再点才发出停止，`Esc` 取消。之后进入收尾，等待识别和翻译处理剩余音频，再保存导出。超过等待限制时应明确告知未完成内容和恢复方式，不能把截断结果冒充完整结果。当前停止收尾等待上限为 60 秒。

### 3.3 下一堂课、窗口与历史

- 下一堂课：保存完成后字幕页底部出现“这堂课已保存”及“下载双语文本 / 下载字幕 SRT / 开始新的一堂课”；点最后一项回到开始页，课程名已清空。每堂课生成新的会话 ID 和独立目录。
- 打开页面时若没有进行中的课，直接显示开始页；上一堂课以“上一堂课”卡片出现，可“查看字幕”，字幕页左上“‹ 返回”回到开始页。若有进行中的课，直接进入字幕页。
- 新标签页或新窗口：打开同一地址即可，所有窗口共享一个活动会话；一个窗口开始的课，其他窗口会自动切到字幕页；在任一窗口结束都会结束这堂课。开始页在别处正在上课时提示“打开字幕 →”。不支持多个窗口各自独立翻译。
- 开始页下方“以前的课”直接列出最近 20 堂（时间、时长、音源，异常结束会标注），每条可下载双语文本和 SRT；尚未实现历史录音回放及逐句编辑。
- 支持系统深色模式；窄屏（≤720px）隐藏部分顶栏信息、时间戳移到句子上方。
- 关闭网页不会结束后台采集；关闭启动终端也不会关闭服务。用户需主动点“结束”并等保存完成。电脑重启后需重新启动。

### 术语与上下文的现行边界

编辑 `outputs/课程术语.csv`，下一次会话读取。兼容原表头 `english,chinese`，词条保留并用于翻译匹配；识别提示现要求新增可选列 `asr_enabled`，值为 `1`、`true` 或 `yes`（不区分大小写）才启用该行。缺列、空值默认不向识别器注入术语，避免跨课程示例默认被声明为本课主题。原 CSV 未删除或改写。最多读取 1,000 个有效词条，每次翻译匹配最多 20 个，显式启用的识别提示最多取前 800 字符。

### 识别质量保护（1.2.2 已实现，真实录音效果待验证）

- 实际核对本机依赖源码：`mlx-whisper==0.4.3` 的 `decode_with_fallback` 对标量温度仅运行一次；`whisperlivekit==0.2.26` 的 LocalAgreement 在转写回调后立即插入假设，`finish()` 直接输出剩余假设。因此在回调返回前验证整个模型结果，在字幕分句前再验证完整 committed/partial 更新，防止长循环先被标点拆成短定稿。
- 连续周期长度 1–8 词，至少 8 次循环且至少 24 词才判为重复异常；不是重复词删除器。短口吃、强调、重复引文和成员变化的列举放行。另检测非有限/倒退/越界时间戳（回退容差 80ms，音频终点容差 250ms）、至少 12 词中超过半数且至少 8 词时长不足 5ms、缺词级时间戳和超过 4,096 词或 32,768 字符输出。阈值是保守工程初值，不能保证区分所有有意长重复与幻觉，也不检测所有语义识别错误。
- 正常窗口仍只用温度 0.0。异常时同一音频最多额外一次温度 0.4 解码，恢复提示仅 `An English lecture.`，不带术语、历史文本，继续关闭 `condition_on_previous_text`。恢复仍须完整通过检查；空恢复、异常返回或调用失败不算成功。缓冲超过 30 秒时不做额外解码，直接记录未恢复，避免对大窗口追加算力。本方案限制调用次数和额外音频范围，不是模型执行的墙钟硬超时。
- 未恢复时不把异常结果传入 LocalAgreement，清空该窗口假设并重置到当前音频终点，后续声音正常接续，不无限重试。保留整窗音频定位（可包含已确认前缀），当前未定稿字幕替换为 `asr_status=unresolved`、`final=false` 的明确缺口；该段不进入翻译队列、翻译背景或 SRT，排队旧预览移除，执行中的旧结果也不能覆盖缺口。原始音频仍在音频日志，需按区间人工核对/导入补处理；本次不实现自动离线补听。
- `asr_quality` 事件含 `status=recovered/unresolved`、会话音频秒数 `start/end`、每次失败原因/温度、最多 4,000 字符的拒绝文本及完整字符数/截断标记；上游原始事件与录音不改写。字幕层兜底拒绝时在段事件中保留拒绝文本摘要和原因。恢复成功只表示结构性质量门通过，仍需 LocalAgreement 正常确认，不代表语义正确。
- 页面中英栏立即撤回缺口旧预览，显示中文异常标记；只看中文同样可见，不显示重新翻译按钮。TXT 写明未确认及时间区间，SRT 排除缺口。`status` 和最终 `session.json` 增加 `asr_unresolved` 计数，详情及结束保存说明提示未恢复处数；`completed` 仍表示处理流程结束，不能解释为全课识别成功。

翻译只在待译文本至少 10 个英文词且以句末标点结束时使用最近两条已定稿英文背景，背景截取最多 1,200 字符。短片段不带背景，以减少小模型重复上一句。术语和上下文只能提供提示，不能承诺一定纠正专业词。

## 5. 架构与不可破坏的约束

```text
麦克风 / 电脑声音 / 导入文件（择一）
  → 16 kHz 单声道 PCM → 五分钟一段的磁盘音频日志
                           ↓ 读取游标
                 VAD + Whisper MLX 流式识别
                           ↓ 带 ID/版本/时间戳的英文片段
                 分句与临时/定稿事件 → 本地事件日志 → 网页
                           ↓ 最新待译版本队列
                 Hy-MT / llama.cpp → 版本校验 → 中文事件 → 网页
                           ↓
                   停止收尾 → WAV、TXT、SRT、元数据
```

1. 收音持续落盘，未识别声音通过磁盘游标读取；不得因队列拥堵静默跳过已接收音频。磁盘写入并不等于承诺断电零丢失，当前未做每块强制刷盘保证。
2. MLX 在单工作线程运行；本地翻译单任务执行。两者都使用 Apple GPU，仍可能争用算力。
3. 每条字幕有稳定 `id`、递增 `revision`、`source`、`start/end`、`final`；译文带 `translated_revision`。英文片段发生修订时，旧译文不得冒充当前定稿。
4. 同片段仅保留一个最新待处理版本，定稿优先；出队复核版本和预览必要性。已经在推理的任务不主动取消，完成后校验、应用或丢弃，并记录执行成本和结果去向。
5. 较旧译文仅在原文仍为有效词边界前缀时可作预览；原文已发生分歧则丢弃；不得覆盖更新的译文。
6. 前端只展示最近约 500 条字幕，完整修订留在磁盘。后端会保留尚未安全完成的片段，所以严重积压时不能宣称所有内存结构都有固定上限。
7. 页面慢或断连不能阻塞推理；客户端事件队列溢出时发完整快照恢复。
8. 不上传录音，不使用云端模型，不在日志或 PRD 中写入本地密钥。启用云端能力须单独明确交互、失败策略及数据边界。

### 当前调度参数

识别按约 1–3 秒音频分块，使用 VAD 跳过静音；模型预热发生在采集计时之前。字幕结合句末标点、较长分句和长度边界进行定稿。

临时预览以**最后实际发出请求的英文版本**为基准：首次至少 4 词（出现数字、否定、单位或条件等关键标记可提前）；后续普通扩句/改写在共同前缀之后新增或改动至少 4 词，且距上次执行至少 1 秒才提交。少量持续变化超过 5 秒后，可在下一次英文更新时触发刷新；这不是译文 5 秒可见保证。数字（含正负号、小数和常见英文数词）、常见单位、否定、条件等关键标记的顺序/数量发生变化时绕过普通词数和冷却门槛。规则为有限英文词表启发式，不等于语义完整性检测。

请求执行超过 5 秒、已有待处理定稿、识别积压或队列等待达到 15 秒时，不新增普通预览；关键变化和定稿仍保留最新待处理版本。最终版本始终进入处理，若与已经成功翻译的英文完全相同则记录复用并更新版本，不重复调用模型。单客户端任务执行、每片段最多一个待处理版本、定稿优先；不丢最终片段，不承诺所有未完成片段的内存总量固定或关键变化立刻显示。原在途慢请求仍可能阻塞后续请求。

没有尝试通过取消客户端请求节省算力。原有 35 秒 HTTP 超时、停止收尾 60 秒上限仍在；超时或收尾取消记录计算停止未确认，不能算作 GPU 工作被取消或算力节省。运行器原有 `--parallel 1` 不变，未用真实 llama.cpp 验证取消。

翻译请求为非流式，超时 35 秒，连接超时 3 秒。仅接受 `finish_reason=stop`、非空有效文字且无未闭合思考段的响应；`length`、缺失结束原因等按未完成处理，保留旧译文并允许运行中重试。不从字符长度推断语义完整，正常 stop 仍可能有语义遗漏，需人工核对。模型加载和首次可听译时间尚未形成稳定统计；后台服务打开成功不代表模型已经预热。

`ready` 目前只检查 `work/deployment.json` 是否存在，不能代表模型完整或权限可用。`translation_wait` 只计算待处理队列中的最长等待，不含正在执行的翻译耗时。

### 翻译指标口径（本次新增，秒）

所有 `translation_attempt` 日志带 `session_id`、片段 `id`、英文 `revision`、`wall_time`、`session_elapsed`；开始与结束事件共享片段/版本。`superseded_pending` 仅表示排队版本被替换，没有执行成本。`started` 与结束事件分开统计，不能将两者加算成两次调用。

| 指标 | 定义与边界 |
|---|---|
| `asr_lag` | 已收音频秒数减识别读取游标，非中文延迟 |
| `finalization_wait` | 当前未定稿片段从首次英文出现到现在的最大时长 |
| `finalization_seconds` | 同一片段首次英文出现到定稿；写入定稿 segment 和请求日志，首次即定稿则为 0；不含此前 ASR 等待 |
| `finalization_audio_lag` | 定稿单调时间减会话音频时钟与该最终音频 end；包含收音/识别/分句等待，仅实时输入有值 |
| `translation_wait` / `queue_seconds` | 前者为最新待处理版本入队至现在的最大时长；后者为该请求版本入队到实际执行；版本替换会重置入队时间，均不含在途执行 |
| `revision_wait_seconds` | 该英文版本出现到执行开始，供检查门槛/排队前等待；与 queue_seconds 重叠，不可相加 |
| `translation_execution_age` | 当前在途请求执行已用时，无在途为 0；另给片段和版本 |
| `execution_seconds` | 每次请求开始至返回、报错或客户端取消；包含 HTTP 传输和服务端等待，不是纯 GPU 时间；被丢弃请求同样记录 |
| `chinese_pending` / `chinese_lag` | 当前中英版本不匹配的片段数，以及这些片段连续未匹配时长最大值；从首次英文出现或上次已匹配后首次修订计起，修订不重置，包含门槛、未定稿、排队和执行，也包括无中文/失败；不是音频末尾延迟，也不是各阶段之和 |
| `revision_age_seconds` / `audio_end_lag` | 请求结束时该请求版本出现后经过时间；实时模式下另记该请求音频 end 至结束时间。过时版本的 audio_end_lag 不能冒充最终中文延迟 |

请求结果区分 `applied_current`、`applied_prefix`、`stale_discarded`、`error`、`request_timeout_compute_unconfirmed`、`client_cancelled_compute_unconfirmed`；出队前过时另记 `superseded_before_start`。旧前缀只作预览，必须保留版本不匹配提示。现有 `translation_seconds` 仍只出现在成功应用的 segment 中，统计真实请求量/成本应使用 attempt 结束记录。相同英文定稿复用只产生 segment 事件，不应计为新调用。

计时差值均使用单调时钟；单调绝对字段仅在同一进程内作差，关联跨进程用会话 ID、版本与墙钟。结束时冻结状态指标，历史缺字段显示“—”。非实时加速导入的音频延迟为空；休眠等时钟异常尚未专项处理。日志不包含浏览器动画完成时间，不能声称测到用户看到完整中文的时刻。正常结束审计最终版本完整性：未匹配/空译文列入 `session.json.incomplete_translation_ids`，会话标记 error；被强制中断时同样保留清单和原因，不自动重试或删除证据。

## 8. 指标与验收方法

| 指标 | 定义与限制 |
|---|---|
| 识别积压 | 已接收音频时长减去识别读取游标；接近零不代表中文已赶上 |
| 待译数量/等待 | 最新待处理版本的数量、最长等待；正在推理的任务另看 `translation_busy` |
| 首次中文延迟 | 某片段首次有效译文出现时间减去该次被翻译音频的结束时间；必须标明仍可修订 |
| 最终中文延迟 | 匹配最终原文的中文就绪时间减去该片段音频结束时间；包含分句等待、识别、排队和翻译 |
| 准确度 | 分开检查英文识别与中文忠实度；优先标注数字、单位、否定、条件、术语错误 |
| 完整性 | 已接收音频是否有文件、最终字幕是否都有匹配译文、有无丢失或重复内容 |
| 资源 | RSS 与 GPU/统一内存分别理解；同时记录 CPU/GPU、温度、电量和磁盘增长，尚无完整基线 |

延迟只在按实时节奏输入时用墙钟比较；离线加速文件处理不能套用相同口径。历史早期的首次译文统计曾受修订重复计数影响，模型对照以最终译文数据为依据。状态日志约每 5 秒持久化，不能把它当成无遗漏的连续峰值采样。

后续延迟优化的最低门槛：同一音频、同一模型、相同术语表和输入节奏做前后对照，报告最终中文延迟的中位数、P95、样本量和失败数，同时检查关键含义。小样本 P95 只作描述，不能据此承诺课堂上限。优化不能以关键错误增加或遗漏音频为代价。

真实课堂先建立用户自己的基线，再确定可接受的延迟目标与错误率；目前不承诺固定秒数或准确率。用户已明确不要求开发者进行 90 分钟课堂测试，真实使用由用户完成并反馈，后续可多次迭代。

## 11. 反馈、验证与交接规则

用户反馈尽量包含：音源与模型、会话/发生时间、实际原话或音频区间、英文结果、中文结果、当时积压情况。先判断收音、ASR、分句、翻译还是展示/保存问题；没有原声或参考文本时，应保留不确定性。

接手开发必须遵守：

1. 先读根目录 `AGENTS.md` 和本文；检查 Git 状态及正在进行的会话，不覆盖未提交修改或打断录音。
2. 保留 `work/`、`.venv/` 与 `outputs/sessions/`。其中有运行必需材料或私人录音，虽然被 Git 忽略也不是可随意删除的废文件。
3. 修改产品代码、模型、默认参数、接口、交互、部署或验证结论时，**在同一次变更中同步更新本文**；内部重构也在变更记录注明是否影响行为。
4. 更新对应章节、待办状态、文档版本/日期及变更记录。只有代码完成不能标验收通过；未运行的检查明确写未验证。
5. 行为改变时同步[使用说明](使用说明.md)。[短测验收报告](短测验收报告.md)保留历史条件，新结果另注明日期与样本，不能用新结论覆盖旧实验事实。
6. 运行与变更相关的检查，避免反复执行与本次改动无关的模型测试；文档修改无需重新跑整套听译。
7. 不要求 90 分钟开发测试；不自动录音或把录音上传 API。多语言、多人重叠、API 均不能被偷偷纳入当前英语优化。
8. 结束交接时写清：修改了什么、测了什么、还缺什么、下次从哪个编号继续。代码与 PRD 一同提交。

给接手 AI 的简短指令：

> 先读取项目根目录 AGENTS.md 和 outputs/PRD.md，按当前实现与待办继续。先核对用户是否在录音，不打断会话。当前仅英语→中文，Small 默认、本地离线优先；用户不要求 90 分钟测试。每次修改同批更新 PRD，对已实现、已验证、待办分别陈述，保留录音及运行材料。先处理用户最新反馈，再按 PRD 优先级推进。
