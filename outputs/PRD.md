## 1. 用户痛点与产品目标

用户在俄罗斯上课，常接触英语、俄语、中文。现有在线翻译有误译、网络慢和卡住的问题；课堂讲话持续进行，用户不能反复点击提交或等待网络恢复。

第一阶段只做好英语→中文：选好音源后点击开始，持续看到英文和中文；中文及时出现，专业词、数字、单位、否定和条件关系尽量准确；网络中断不影响核心识别、翻译与保存。错误必须能追溯到英文识别、中文翻译及原始声音，便于下一次迭代。

产品判断：先使用本机可持续运行的轻量模型，通过收音质量、术语、分句和调度改善体验。不能仅靠加大模型、接入 API 或宣传“支持多语言”来推断课堂效果。速度与准确度发生冲突时，应保留可修订预览和清晰状态，禁止通过漏掉音频或擅自补写内容制造流畅感。

### 范围边界

- 当前实现：英语识别、简体中文翻译、单音源、单活动会话、本地保存。
- 后续预留：固定俄语→中文，再评估同一人中英俄切换；需实际混说样本验收。
- 单独研究：多人重叠说话与说话人区分。语言切换不等于多人识别，二者不得混用验收结论。
- 云端 API 可作为未来自愿启用的补充；当前未接入，离线链路必须始终独立可用。
- 本版不包含多人同时独立听译、系统开机自启、通用安装包、Windows/Linux 适配。

## 2. 真实环境与模型决策

已核对实际本机：MacBook Air（Mac16,13），Apple M4，10 核 CPU、10 核 GPU，16 GiB 统一内存，macOS 26.3.1 arm64。系统信息、内置显示器和 APFS 磁盘用于确认是用户 Mac，而非云端容器。最初可用磁盘约 265 GiB，仅代表当时快照。

| 组件 | 当前选择与依据 |
|---|---|
| 默认识别 | `mlx-community/whisper-small-mlx`，多语言权重，运行时固定英语；短样例上更及时 |
| 可选识别 | `mlx-community/whisper-large-v3-turbo`，停止会话后切换作课堂对照 |
| 流式处理 | WhisperLiveKit 0.2.26 的 MLX/OnlineASRProcessor 组件；未直接部署其完整网页应用 |
| 翻译 | Hy-MT2-1.8B GGUF Q4_K_M，本地 llama.cpp b11669；日志确认 33/33 层使用 Apple GPU |
| 推理环境 | 独立 Python 3.12.15、MLX 0.32.4、mlx-whisper 0.4.3；完整 Python 依赖见 `requirements.lock` |
| 采集 | Swift 原生程序：麦克风 AVAudioEngine；电脑声音 ScreenCaptureKit；文件用随依赖提供的 FFmpeg |
| 页面与服务 | 本地静态 HTML/CSS/JS、FastAPI、WebSocket；无需 CDN |

没有替换系统原有 Python。模型精确来源、revision、SHA256 和运行包校验信息在本机 `work/downloads/verified-manifest.json`；该文件与模型当前未纳入 Git。迁移问题见第 10 节。

### 存储和内存预算

模型文件约：Small 481 MB、Turbo 1,614 MB、Hy-MT 1,133 MB，共约 3.23 GB；只计算默认 Small + Hy-MT 则约 1.61 GB。以上是十进制文件体积，不是内存需求。

本机完整开发目录此前约 6 GiB，包含两个识别模型、翻译模型、下载包、环境与缓存。当前 `.venv` 约 1.3 GiB。短测进程及子进程 RSS 合计峰值约 2.6 GiB，未完整衡量 GPU/统一内存，不能当作总内存上限。

音频格式为 16 kHz、单声道、16 位 PCM。每小时原始 PCM 约 115.2 MB；正常保存还生成 WAV，并保留 PCM，因此两份约 230.4 MB/小时，另加事件和导出文件。导入原文件还会占用 `work/uploads/` 空间。当前无自动清理策略。

## 3. 用户流程与交互要求

### 3.1 开始一堂课

1. 双击 `outputs/启动课堂翻译.command`，或运行 `.venv/bin/python scripts/launch.py`。
2. 启动器创建脱离启动终端的后台服务；重复打开复用已有服务。打开网页不会自动录音。
3. 页面地址为 `http://127.0.0.1:8767/`。旧的 8766 是临时下载面板，不是产品入口；8768 是内部翻译服务。
4. 填课程名，选择麦克风、电脑声音或导入文件；默认 Small。点击开始，等待模型加载后持续听译。
5. 按 macOS 提示授予采集权限；权限或音源错误需在页面可见，不得只写日志。

麦克风使用系统当前默认输入设备，尚无设备选择器。电脑声音捕获其他应用播放的音频，尚无按应用选择。一次只能使用一种音源，尚不能混合麦克风和系统声音。导入文件上限为 1 GiB，实际可解码格式取决于 FFmpeg；不是所有后缀都已逐一验证。

### 3.2 听译与停止

页面展示时间戳、英文原文、中文、字幕状态、音量、识别积压、翻译等待和进程内存。临时中文允许修订。界面的“已确认”表示原文已定稿且译文匹配该原文版本，不表示人工证明内容正确。

点击“停止并保存”后进入收尾，等待识别和翻译处理剩余音频，再保存导出。超过等待限制时应明确告知未完成内容和恢复方式，不能把截断结果冒充完整结果。当前停止收尾等待上限为 60 秒。

### 3.3 下一堂课、窗口与历史

- 下一堂课：停止当前会话，等待保存结束，修改课程名/音源，再点开始；生成新的会话 ID 和独立目录。
- 新标签页或新窗口：打开同一地址即可，但所有窗口共享一个活动会话；在其中一个窗口停止，会影响同一会话的其他窗口。
- 当前没有独立“新建一堂课”按钮，也没有多个窗口各自独立翻译的能力。
- 历史记录可下载导出文件；尚未实现完整历史录音回放及逐句编辑。
- 关闭网页不会结束后台采集；关闭启动终端也不会关闭服务。用户需主动停止并保存。电脑重启后需重新启动。

### 术语与上下文的现行边界

编辑 `outputs/课程术语.csv`，表头为 `english,chinese`，下一次会话读取。当前最多读取 1,000 个有效词条，每次翻译匹配最多 20 个，识别提示最多取前 800 字符。

翻译只在待译文本至少 10 个英文词且以句末标点结束时使用最近两条已定稿英文背景，背景截取最多 1,200 字符。短片段不带背景，以减少小模型重复上一句。术语和上下文只能提供提示，不能承诺一定纠正专业词。

## 5. 架构与不可破坏的约束

```text
麦克风 / 电脑声音 / 导入文件（择一）
  → 16 kHz 单声道 PCM → 五分钟一段的磁盘音频日志
                           ↓ 读取游标
                 VAD + Whisper MLX 流式识别
                           ↓ 带 ID/版本/时间戳的英文片段
                 分句与临时/定稿事件 → 本地事件日志 → 网页
                           ↓ 最新待译版本队列
                 Hy-MT / llama.cpp → 版本校验 → 中文事件 → 网页
                           ↓
                   停止收尾 → WAV、TXT、SRT、元数据
```

1. 收音持续落盘，未识别声音通过磁盘游标读取；不得因队列拥堵静默跳过已接收音频。磁盘写入并不等于承诺断电零丢失，当前未做每块强制刷盘保证。
2. MLX 在单工作线程运行；本地翻译单任务执行。两者都使用 Apple GPU，仍可能争用算力。
3. 每条字幕有稳定 `id`、递增 `revision`、`source`、`start/end`、`final`；译文带 `translated_revision`。英文片段发生修订时，旧译文不得冒充当前定稿。
4. 同片段仅保留最新的待处理翻译，定稿优先。已经在推理的旧临时任务目前不会被取消，完成后再检查是否还能使用。
5. 较旧译文仅在原文仍为有效词边界前缀时可作预览；原文已发生分歧则丢弃；不得覆盖更新的译文。
6. 前端只展示最近约 500 条字幕，完整修订留在磁盘。后端会保留尚未安全完成的片段，所以严重积压时不能宣称所有内存结构都有固定上限。
7. 页面慢或断连不能阻塞推理；客户端事件队列溢出时发完整快照恢复。
8. 不上传录音，不使用云端模型，不在日志或 PRD 中写入本地密钥。启用云端能力须单独明确交互、失败策略及数据边界。

### 当前调度参数

识别按约 1–3 秒音频分块，使用 VAD 跳过静音；模型预热发生在采集计时之前。字幕结合句末标点、较长分句和长度边界进行定稿。

临时翻译当前条件是**该段总词数至少 4 个**、同片段距上次提交至少 1 秒、识别积压和待译等待均低于 15 秒；定稿不受此预览限制。这不等于“新增 4 个词才重译”。页面在积压超过 15/30 秒时分别提示追赶/明显落后。

翻译请求为非流式，超时 35 秒，连接超时 3 秒。模型加载和首次可听译时间尚未形成稳定统计；后台服务打开成功不代表模型已经预热。

## 6. 数据、接口与本机边界

### 文件约定

| 位置 | 用途与维护要求 |
|---|---|
| `outputs/sessions/<id>/session.json` | 会话名、音源、模型、语言、状态、起止时间及延迟记录 |
| 同目录 `events.jsonl` | 追加字幕/译文修订、状态及错误；可按最新版本重建字幕 |
| 同目录 `audio_*.pcm` / `audio_*.wav` | 五分钟音频分段；WAV 正常结束时由 PCM 生成，两者保留 |
| 同目录 `双语记录.txt` / `双语字幕.srt` | 可读记录与字幕；SRT 仅导出原文已定稿且译文版本匹配的片段 |
| `work/app.log` / `work/llama-server.log` | 页面服务与本地模型日志；可包含调试数据，分享前检查 |
| `work/downloads/` / `work/runtime/` / `.venv/` | 本机模型、安装材料、运行时及环境；不能当普通临时文件删除 |
| `work/uploads/` | 导入源文件；当前无自动删除 |

不自动上传、删除或覆盖历史课。异常退出时可以恢复已收到的音频和已写入事件，不能补回从未采集到的声音。恢复脚本重建导出与 WAV，不会自动重新推理。

### 接口交接表

| 接口 | 当前协议 |
|---|---|
| `GET /api/state` | 返回 `token, session, segments, ready`；无活动会话时 `session=null` |
| `POST /api/uploads` | multipart 文件；返回 `id,name,bytes`，空文件 400、超过 1 GiB 413 |
| `POST /api/sessions` | JSON：`source` 为 `microphone/system/file`；`model` 为 `small/turbo`；`title`；文件需 `upload_id`；`realtime` 默认 true；返回会话 `id` |
| `POST /api/stop` | 等待停止收尾；返回 `ok` |
| `POST /api/retry/{segment_id}` | 当前未关闭队列的活动会话可重试；结束后返回 409 |
| `GET /api/sessions` | 最近最多 100 条会话元数据 |
| `GET /api/export/{session_id}/{kind}` | `kind=txt/srt/events`；TXT/SRT 从事件重建 |
| `WS /ws?token=…` | `snapshot/segment/status/error/capture/ping` 等事件；快照含状态和近期字幕 |

8767 仅绑定 loopback；写请求校验 `x-session-token` 和允许的 Origin，WebSocket 校验 token 与 Origin。8768 仅绑定 loopback，并使用本地密钥文件。这是本机应用的访问约束，不是公网部署方案；不得直接改为公网监听。

`ready` 目前只检查 `work/deployment.json` 是否存在，不能代表模型完整或权限可用。`translation_wait` 只计算待处理队列中的最长等待，不含正在执行的翻译耗时。

从项目根目录运行：

```sh
# 读取当前会话状态；不要分享输出中的 token
curl -s http://127.0.0.1:8767/api/state

# 启动或复用服务；不会自动开始录音
.venv/bin/python scripts/launch.py

# 不打开浏览器的同等启动方式
.venv/bin/python scripts/launch.py --no-browser

# 逻辑测试与网页语法检查（不启动录音）
.venv/bin/python -m unittest discover -s tests -v
node --check classroom/static/app.js
git diff --check

# 仅对已结束/中断的指定会话操作；替换为实际编号
.venv/bin/python scripts/recover_session.py '替换为实际会话编号'
```

界面打不开时先检查 8767 的 `/api/state` 和 `work/app.log`，再检查进程、端口冲突和环境。曾观察到服务未运行，但没有足够证据确定当时退出原因；现有启动器已解决服务依附启动终端的问题。不要仅刷新旧 8766 下载页面。

模型测试、`scripts/smoke.py`、`scripts/check_http.py` 可能占用模型或创建会话；先检查用户是否正在录音，禁止中断已有会话。部分开发短测依赖 `work/` 中未纳入 Git 的样例，克隆后不能假定可直接运行。

## 8. 指标与验收方法

| 指标 | 定义与限制 |
|---|---|
| 识别积压 | 已接收音频时长减去识别读取游标；接近零不代表中文已赶上 |
| 待译数量/等待 | 最新待处理版本的数量、最长等待；正在推理的任务另看 `translation_busy` |
| 首次中文延迟 | 某片段首次有效译文出现时间减去该次被翻译音频的结束时间；必须标明仍可修订 |
| 最终中文延迟 | 匹配最终原文的中文就绪时间减去该片段音频结束时间；包含分句等待、识别、排队和翻译 |
| 准确度 | 分开检查英文识别与中文忠实度；优先标注数字、单位、否定、条件、术语错误 |
| 完整性 | 已接收音频是否有文件、最终字幕是否都有匹配译文、有无丢失或重复内容 |
| 资源 | RSS 与 GPU/统一内存分别理解；同时记录 CPU/GPU、温度、电量和磁盘增长，尚无完整基线 |

延迟只在按实时节奏输入时用墙钟比较；离线加速文件处理不能套用相同口径。历史早期的首次译文统计曾受修订重复计数影响，模型对照以最终译文数据为依据。状态日志约每 5 秒持久化，不能把它当成无遗漏的连续峰值采样。

后续延迟优化的最低门槛：同一音频、同一模型、相同术语表和输入节奏做前后对照，报告最终中文延迟的中位数、P95、样本量和失败数，同时检查关键含义。小样本 P95 只作描述，不能据此承诺课堂上限。优化不能以关键错误增加或遗漏音频为代价。

真实课堂先建立用户自己的基线，再确定可接受的延迟目标与错误率；目前不承诺固定秒数或准确率。用户已明确不要求开发者进行 90 分钟课堂测试，真实使用由用户完成并反馈，后续可多次迭代。

## 10. 已知缺口与下一步优先级

以下是待办，不是本次文档交付已完成的功能。P1 优先解决影响可信度与主要体验的问题；P2 改善使用便利性；P3 为范围扩展。

| 编号/优先级 | 问题、证据与实施方向 | 完成标准 |
|---|---|---|
| B01 / P1 | 等待偶有长尾；旧临时翻译即使已过时仍占推理时间。先增加阶段计时，再对照减少无效重译 | 同样本前后对照，尾延迟改善或原因可解释，关键含义与音频完整性不退步 |
| B02 / P1 | 当前 4 词门槛算总词数，容易重复提交。候选为新增 3–4 词才重译，数字/否定/单位变化优先 | 针对数字改写、否定和普通扩句验证，降低无效翻译次数且关键变化及时出现 |
| B03 / P1 | `translation_wait` 不含执行时间，页面识别积压容易被误解为中文延迟 | 分开显示识别、排队、执行及中文落后；明确定义时间基准并覆盖定稿等待 |
| B04 / P1 | `session.json` 主要在开始和结束写入，中断后可能遗留 loading；已有旧开发会话留存 PCM、未完成 WAV | 非活动会话可识别为中断；恢复不会误改正在录音的会话；明确恢复范围及成功状态 |
| B05 / P1 | 静态核对发现 TXT 的“已确认”只取原文 final，未像 SRT 那样要求译文版本匹配；存在误导风险 | 构造原文定稿但中文过期/失败样例，TXT 明确原文与译文各自状态，与页面/SRT 语义一致 |
| B06 / P1 | 部署脚本从被忽略的 `work/download_models_parallel.py` 导入清单，依赖本机安装材料；干净克隆不能独立复现部署 | 清单、下载及校验逻辑纳入版本管理，固定来源/版本，支持本地材料离线安装并说明迁移限制 |
| B07 / P1 | `ready` 仅代表部署标记存在；模型缺失、端口冲突或权限未就绪仍可能开页成功 | 区分服务可访问、资源可用、模型加载与采集权限，错误信息指向可执行的恢复动作 |
| B08 / P2 | 下一堂课操作不够直观；用户曾询问新窗口如何使用 | 明确“新建一堂课”流程；进行中不误清空/停止，历史保留，窗口共享状态有提示 |
| B09 / P2 | 术语靠 CSV；历史不能逐句回放/重译；模型空闲仍驻留且无退出服务按钮 | 分步提供术语编辑、定位录音和安全退出/释放模型；每项单独验收 |
| B10 / P2 | PCM/WAV、上传、缓存无清理；保存完成信号与文件落盘顺序需专门检查 | 有空间提示及可理解的保留策略；未保存完不显示完成；删除需明确用户操作 |
| B11 / P3 | 俄语和混说未实现 | 先独立固定俄语验收，再用同人三语切换、多人重叠两类不同数据验证；支持语言设置扩展 |
| B12 / P3 | 云端 API、替代识别器、完整安装包尚未接入 | 离线主链不退化；明确成本/数据与断网行为，实际样本证明收益后再采用 |

取消正在推理的过时任务仅是候选优化，必须确认 llama.cpp 实际停止计算；只丢弃 HTTP 结果不代表省下 GPU 时间。按语义更早定稿也需保护条件、否定和数字，不得简单按固定字数切断。当前没有“积压时自动合并最终段落”的实现，不能在界面或文档中宣称已有。

建议下一次开发先完成 B05 的可信导出与 B03/B01 的测量，再基于用户问题片段实施 B02；B04、B06、B07 在扩大试用或迁移前补齐。一次迭代围绕可复现痛点，避免同时换模型、改分句、改提示词导致无法归因。

## 11. 反馈、验证与交接规则

用户反馈尽量包含：音源与模型、会话/发生时间、实际原话或音频区间、英文结果、中文结果、当时积压情况。先判断收音、ASR、分句、翻译还是展示/保存问题；没有原声或参考文本时，应保留不确定性。

接手开发必须遵守：

1. 先读根目录 `AGENTS.md` 和本文；检查 Git 状态及正在进行的会话，不覆盖未提交修改或打断录音。
2. 保留 `work/`、`.venv/` 与 `outputs/sessions/`。其中有运行必需材料或私人录音，虽然被 Git 忽略也不是可随意删除的废文件。
3. 修改产品代码、模型、默认参数、接口、交互、部署或验证结论时，**在同一次变更中同步更新本文**；内部重构也在变更记录注明是否影响行为。
4. 更新对应章节、待办状态、文档版本/日期及变更记录。只有代码完成不能标验收通过；未运行的检查明确写未验证。
5. 行为改变时同步[使用说明](使用说明.md)。[短测验收报告](短测验收报告.md)保留历史条件，新结果另注明日期与样本，不能用新结论覆盖旧实验事实。
6. 运行与变更相关的检查，避免反复执行与本次改动无关的模型测试；文档修改无需重新跑整套听译。
7. 不要求 90 分钟开发测试；不自动录音或把录音上传 API。多语言、多人重叠、API 均不能被偷偷纳入当前英语优化。
8. 结束交接时写清：修改了什么、测了什么、还缺什么、下次从哪个编号继续。代码与 PRD 一同提交。

给接手 AI 的简短指令：

> 先读取项目根目录 AGENTS.md 和 outputs/PRD.md，按当前实现与待办继续。先核对用户是否在录音，不打断会话。当前仅英语→中文，Small 默认、本地离线优先；用户不要求 90 分钟测试。每次修改同批更新 PRD，对已实现、已验证、待办分别陈述，保留录音及运行材料。先处理用户最新反馈，再按 PRD 优先级推进。
