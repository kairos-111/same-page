## 1. 产品定位与品牌

### 1.1 定位

Same Page 帮用户听懂正在听的外语：把声音变成可对照阅读、保存和回看的原文字幕与中文译文。课堂是起点场景，但不是产品边界——讲座、视频、网课、已有录音都适用。

核心链路：**获取声音 → 原文字幕与译文 → 结束保存 → 阅读、导出与录音管理**。

要解决的问题：

- 持续讲话时，一句没听懂会影响后面的理解；不能要求用户逐句提交。
- 识别或翻译慢时，用户分不清是没收到声音、正在计算还是漏掉了。
- 专业词、数字、否定、条件和单位出错会改变原意；读着通顺不等于准确。
- 依赖云端时网络一断就停；用户希望在本机持续工作，并自己决定录音是否保留。
- 结束后要能直接阅读和核对，而不只是下载文件。

### 1.2 品牌（已落实）

- 名称 **Same Page**（单词间保留空格），来自 “on the same page”。不另设中文品牌名，不再用“听课”作产品名。
- 主 slogan **每一句，都跟得上。** 唯一主口号，不替换、不省略。
- 副标题：本地 AI 驱动的英俄中三语实时传译工具。
- 图标：“声波成字”（深绿底、薄荷绿声波、米白三行字幕，纯色无渐变），源文件 `desktop/icons/generate.swift`。

产品介绍定稿：

> Same Page 用本地 AI，将你正在听的英语、俄语或中文转为原文字幕与对应译文。无论声音来自麦克风、电脑播放，还是已有录音，都可以边听边看、随时对照，让理解跟上内容的节奏。
>
> 借助 AI 对语境的理解，更准确地还原表达。识别与翻译在你的电脑上完成，无需将录音上传至云端，不依赖网络连接，断网也能继续。
>
> 结束后，继续阅读双语记录，或导出文字与字幕；录音是否保留，由你决定。
>
> **本地 AI · 三语传译 · 离线可用 · 记录可回看**

文案边界：“更准确”不等于零误差；“离线可用”不保证不卡顿或设备不休眠；“三语传译”不代表反向互译、三栏译文或语音播报；“每一句，都跟得上”是体验目标，不是固定秒数承诺。

### 1.3 不做的事（除非用户另行提出）

多人分离/说话人识别、反向或六向互译、语音播报、自动总结、聊天助手、云端 API、账号系统。

## 3. 当前功能（0.10.2）

### 3.1 界面结构

左侧导航：**开始翻译、我的记录、运行数据、设置**。侧栏模型区是一个状态按钮（“N/3 运行中 / 未加载 / 正在处理…”），点击进设置页。侧栏底部只有一行浅灰小字“🔒 仅在本机处理 · 0.10.2”（开发版显示“开发版 0.10.2”），没有单独的退出按钮。

### 3.2 开始

- 声音来源三选一：**麦克风**（系统默认输入，无设备选择）、**电脑声音**（整机播放声音，不按应用筛选）、**导入文件**（音视频，上限 1 GiB）。
- 语言三选一按钮：英语 / 俄语 / 英俄中混合（试用），支持方向键；记住上次选择；会话中锁定。
- 模型在开始按钮旁下拉：“标准 · Small”（默认）/“更准 · Turbo”。记录名称可不填，默认“新记录”。
- ⌘↵ 开始（输入法组字时不触发）。打开应用或启动模型**绝不自动录音**。
- 收音在模型加载期间就开始，开头的话不丢；麦克风接通前显示“正在启动麦克风…”。
- 导入文件不按原速处理，显示识别进度/百分比；中途结束只识别到当前位置，其余标为未处理区间。

### 3.3 实时字幕

- 原文与译文左右两栏（≤900px 上下），按段落分组；原文/译文字号分别调整（8 档 13–36px，默认 17px）；可“只看译文”。
- 新字约 40ms 一跳逐字出现；修订只淡出/淡入差异部分。默认自动跟随，上翻暂停并显示“回到最新”。
- 原文修订时保留旧译文作为待更新预览，但不能冒充匹配当前版本。
- 顶栏：延迟标签、显示、导出、结束。延迟标签取识别落后、翻译排队、中文未跟上三者最大值：<4 秒“已跟上”，<15 秒“延迟约 N 秒”，否则“落后 N 秒”（黄色）；结束后显示“详情/待核查 N 处”。
- 导出菜单：复制全部、TXT、SRT、Markdown。
- **正文不插入任何识别缺口提示**（无黄色卡片、系统行或空段）；被拒绝的旧预览立即撤回；缺口范围与完整性信息只在“详情”里看。断连、采集停止等阻断错误仍明确提示。

### 3.4 结束与保存

- 结束需两次点击确认（3 秒内）；采集停止后等识别/翻译队列收尾，生成导出和录音后才显示“本次记录已保存”。`completed` 只表示流程结束，不代表逐词完整。
- 保存后弹“保留本次录音吗？”，只有**保留 / 不保留**两项，Esc 不能跳过；不保留只删录音，文字和记录保留。
- 录音只存一份：结束时把五分钟 PCM 暂存合并为单个 `audio_0000.wav`，核对帧数后删 PCM；失败则保留 PCM 供恢复。

### 3.5 我的记录

- 顶部累计数据条：总时长与语言分布、记录数、句数、译文字数、近 14 天活动格与连续天数。
- 标题搜索；点击直接阅读全量原文/译文（不重放逐字动画）；TXT/SRT 导出；在访达定位录音；应用内回放（单个可拖动 WAV，旧记录多段拼成一条，换记录时释放播放器）。
- 两种删除，都用应用内确认框（默认焦点“取消”，Esc 取消）：**删除录音**（立即永久删除音频，保留文字）；**删除记录**（移入 `outputs/sessions/.trash/`，可恢复或彻底删除）。
- 收藏、备注、“待核查”筛选。活动中或仍在写入的记录拒绝删除；导入文件不删用户原件，有共享引用的上传副本不误删。

### 3.6 运行数据

从每条记录的 `events.jsonl` 只读计算（`classroom/metrics.py`，不写记录、不输出识别文本）。

- 总览：出字延迟中位数、五档延迟分布、定稿延迟/识别落后峰值/待核查、每次记录的中位数与 95% 趋势、记录列表。可按近 7/30 天/全部、Small/Turbo 筛选。
- 单条诊断：整场时间线（落后热力条、事件刻度、每句出中文延迟，点击跳到字幕）、“一句话的时间花在哪”（等待定稿/排队/翻译）、异常事件筛选、日志统计、可复制诊断摘要。
- 较早记录缺少分阶段计时时标注“旧记录”。

### 3.7 模型与退出

- 三个模型：Small、Turbo（识别）、Hy-MT（翻译）。两套识别权重可同时驻留，每次会话只用选定的一个，流式/VAD/上下文状态每次新建。
- **打开应用自动加载全部三个模型**（正在翻译、已全部运行或资源缺失时跳过）；设置页仍可一键启动、全部停止和逐项启停，状态文字“运行中/已停止”。活动会话及保存时禁止手动启停。
- 退出（⌘Q 或关闭窗口）弹确认“退出将关闭所有模型……”；确认后先结束并保存当前记录，再关闭所有模型（若仍在加载最多等约 30 秒），然后退出。只停止应用自己管理的后台进程。

## 4. 语言与识别规则

### 4.1 三种模式

| 模式 | 识别 | 翻译 |
|---|---|---|
| 英语→中文 | 固定英语转写 | Hy-MT 直接译中文 |
| 俄语→中文 | 固定俄语转写 | Hy-MT 直接译中文 |
| 英俄中混合（试用） | 按静音边界分段，逐段探测语言后转写 | 外语片段译中文；中文片段由程序保留，不经英文中转 |

- 所有 Whisper 调用（含预热、恢复）显式 `task=transcribe`，**不使用不限语言的自动解码**。旧请求未带 `language_mode` 时默认 en。
- 混合模式：静音边界 ≥120ms（前段 ≥900ms、后段 ≥800ms）；无分界时探测最近最多 6 秒；每轮最多 8 次语言探测、4 个语段转写。语言探测在 en/ru/zh 内按相对概率并结合稳定语言先验选提示——**绝对概率不是质量门**；稳定先验取**最后一个明确的声学探测**，不能被含弱片段的合并区段覆盖。短弱段先与相邻同语言片段合并再解码。
- 混合模式遇到暂时无法判定或质量异常时，**最多等待 2 秒新音频**（`waiting`）：不清缓冲、不进字幕、不送翻译、不强制定稿；结束、积压 ≥15 秒、覆盖恢复内部或窗口 >30 秒时不等待。仍不合格才走有限恢复/缺口路径。
- 转写缓存仅在同一音频区间、内容指纹、语言、温度完全相同时复用，每轮讲话/新会话重置。混合模式不把前一语言的识别历史或术语提示带到下一语言。
- 中文统一简体：本地 OpenCC t2s（opencc-python-reimplemented 0.1.7，内置字典，不联网），覆盖原文、译文、中文直通、历史阅读投影和新导出；转换前文本存 `source_raw`/`translation_raw` 供审计，历史事件原件不回写。
- 纯中文在识别阶段直接复制到译文栏（`translation_origin=source_zh`），过时的在途翻译不能覆盖它。

已知限制：同句无明显停顿的语言切换可能被按主导语言改写或漏词；轻声、短外语夹词、口音、噪声和长时表现未充分验证。

### 4.2 质量保护

- 重复循环检测（1–8 词周期、≥8 次、≥24 词；同一符号或字母连续/间隔重复 ≥24 次）、异常时间戳、超长输出、范围外语言/字母脚本 → 判为异常。这不是重复词删除器，正常强调、口吃、引文放行。
- 异常时同一音频最多额外一次温度 0.4 解码；积压 >5 秒或缓冲 >30 秒时不做额外解码。仍失败则记为缺口（`asr_status=unresolved`），保留时间区间和拒绝文本，不送翻译、不进 SRT，**不靠删字伪装成功**。
- 乱码清理（`clean_asr_text`）：只保留拉丁/西里尔/汉字/数字/标点，去掉 4 个以上重复标点；无汉字且字母数字少于 2 个视为乱码——预览不显示，定稿记为待核查（`asr_reason=garbage_text`），不送翻译。
- WLK 无进展重置前复制未确认区间（最多 15 秒），最多两次一致解码才提交；同一讲话最多 2 次恢复。超出范围记 `gap`（待核查区间，不等于已证明漏听）。
- 结束时从全量 `events.jsonl` 重建并核对：缺口区间、未匹配译文 ID、未处理区间，写入 `session.json` 的 `integrity`。

### 4.3 术语

`outputs/课程术语.csv`，表头兼容 `english,chinese`，可选 `source`、`russian`、`asr_enabled` 列。只有 `asr_enabled` 为 1/true/yes 的行才注入识别提示（按模式过滤脚本）；翻译匹配每次最多 20 条。网页内编辑未做（用户暂缓）。

## 5. 架构与关键参数

### 5.1 链路

```text
麦克风 / 电脑声音 / 导入文件（三选一）
  → 16 kHz 单声道 PCM → 五分钟一段的磁盘音频日志（不因拥堵丢音频）
  → VAD + Whisper 流式识别（单工作线程，LocalAgreement 确认）
  → 带 id / revision / 时间戳的原文片段 → 分句、预览/定稿事件 → events.jsonl → 界面
  → 最新版本翻译队列（定稿优先）→ Hy-MT2 / llama.cpp → 版本校验 → 译文事件
  → 结束收尾 → WAV、TXT、SRT、session.json
```

桌面外壳：Mac 为 Tauri/Rust 窗口；内置 Python 3.12 + FastAPI + WebSocket，静态 HTML/CSS/JS，无 CDN。

### 5.2 模型

| 组件 | Mac | Windows |
|---|---|---|
| 识别 | MLX Whisper Small（默认，481 MB）/ large-v3-turbo（1.6 GB） | faster-whisper（CTranslate2，CPU int8）Small；不带 Turbo |
| 流式 | WhisperLiveKit 0.2.26 LocalAgreement | 同一算法，代码内置在 `classroom/wlk/`（避免引入 torch） |
| VAD | Silero | Silero ONNX，numpy 实现 `NumpyVAD` |
| 翻译 | Hy-MT2 1.8B GGUF Q4_K_M（1.1 GB，Apache 2.0），llama.cpp b11669，Apple GPU | 同模型；llama.cpp Vulkan 优先，失败自动改 CPU |
| 采集 | Swift 助手（AVAudioEngine / ScreenCaptureKit），导入用 FFmpeg | soundcard（WASAPI，电脑声音用 loopback），导入用 PyAV |

Small 作默认的依据：15.9 秒合成英语短测中，最终中文延迟中位 Small 约 1.85 秒、Turbo 约 6.26 秒，关键含义两者都保留。这不是“Small 更准”的结论。

### 5.3 现行调度参数（2.5.0 三批提速后）

| 项 | 值 |
|---|---|
| 识别步长 | 英语/俄语单语实时：上次解码 <0.35 秒时每 0.5 秒一次，否则 1 秒；混合模式与导入文件每 1 秒 |
| 重解码窗口 | 6 秒 |
| Whisper 输出上限 | `min(224, 24 + 12×音频秒数)` 个 token |
| 定稿 | 停顿从最后一个有声帧起算：1 秒；句末为句号/问号等 0.5 秒；一句连续超过 6 秒时 0.3 秒换气即定稿 |
| 预览翻译 | 3 词起，之后每新增 2 词更新，间隔 ≥0.8 秒、最长 3 秒必刷新；数字/否定/单位/条件变化优先 |
| 翻译请求 | 预览 3 秒、定稿 6 秒超时（Windows 8/15 秒），定稿超时重试一次；输出长度 `min(320, 32 + 3×原文字数)`；只接受 `finish_reason=stop` |
| 翻译背景 | 待译文本 ≥10 词且以句末标点结束时，带最近两条定稿原文（≤1,200 字符） |
| 背压 | 每片段只留一个最新待处理版本，定稿优先；积压 >5 秒不额外重解码 |
| 前端 | 实时只保留最近约 500 条字幕，完整修订在磁盘 |

提速前基线（独立版 21 条记录、4 小时 15 分、2,320 句）：出字延迟中位 4.3 秒、95% 约 14 秒。目标中位约 2–2.5 秒、95% 约 6–8 秒。**提速后的真实收益还没测**，以后在“运行数据”页用新记录对照。

### 5.4 Windows 版

**已做：**

- 平台层 `classroom/system.py`（后端选择、模型目录、采集/解码命令、llama 候选、打开文件夹）；`classroom/ct2_asr.py`（faster-whisper 适配，返回与 MLX 相同的结构）；`classroom/capture_windows.py`、`classroom/decode_file.py`。

## 7. 不可破坏的规则

1. 原音频持续落盘，不能靠丢音频换低延迟。
2. 识别异常留缺口和时间区间，不删字伪装恢复；原文、译文分别保留版本，旧结果不能覆盖新结果或缺口。
3. 适配器返回 `(committed, partial, flush)`，可能带第四项 `{events, rejected, waiting}`；`waiting=True` 时不能清缓冲、强制 flush、定稿或送翻译；拒绝时禁止强制 flush。
4. 语义正确、流程完成、版本匹配、音频完整是四件事，分别判断。
5. 应用包放程序和模型，用户目录放记录与偏好；用户已删的记录不能因迁移旧副本而恢复。
6. 不自动录音、不上传录音、不启用云端 API；日志可能含文本，不默认上传诊断；不把令牌、密钥写进文档或提交。
7. 启停、重启或占用模型前先查对应端口的 `/api/state`；有 loading/running/draining 会话时不干扰。
8. 不做 90 分钟长测；真实使用由用户完成并反馈。
